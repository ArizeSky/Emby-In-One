## 1. 设计原则

做视觉决策时用这六条尺子，冲突时按序号优先：

| # | 原则 | 落地含义 |
|---|------|----------|
| P1 | **内容优先，chrome 退后** | 海报/视频是主角；控制层（工具栏、菜单）在悬停/播放时浮现，静止时退场 |
| P2 | **一屏一焦点** | 每屏只有一个视觉锚点（首页=Hero，库页=筛选栏，播放页=画面），其余元素降明度 |
| P3 | **分层靠明度，不靠描边** | 用 bg-0→bg-3 的明度阶梯 + 阴影表达层级；边框只用于交互反馈（hover/focus），不做静态装饰 |
| P4 | **动效必须有因果** | 每个动画对应一次状态变化（数据到达、悬停、切换），禁止纯装饰动画 |
| P5 | **语义色克制** | 金/紫/绿只出现在规格徽章与状态点，绝不大面积使用；主色渐变只用于主按钮与激活态 |
| P6 | **可达性是底线不是加分项** | 对比度、焦点态、命中区域在验收清单里，不达标不算完成 |

## 2. 令牌细化与 v1.1 修订

### 2.1 对比度实测 → 两处修订

对 v1.0 色板按 WCAG 2.1 公式实测（前景 vs `--bg-1 #0D1322`）：

| 组合 | 对比度 | AA(4.5) | 结论 |
|------|--------|---------|------|
| `--t1 #F1F5F9` on bg-1 | ≈ 15.9:1 | ✅ AAA | 主文字，任意尺寸 |
| `--t2 #94A3B8` on bg-1 | ≈ **7.2:1** | ✅ AAA | 辅助文字，任意尺寸 |
| `--t3 #5B6B85` on bg-1 | ≈ **3.4:1** | ❌ | **仅限装饰性 caption / 占位符**，必要辅助信息一律 t2 |
| 白字 on `#6366F1`（v1.0 渐变起点） | ≈ 4.5:1 | ⚠️ 临界 | 14.5px 按钮文字不达标 |
| 白字 on `#8B5CF6`（v1.0 渐变终点） | ≈ 4.2:1 | ❌ | 不达标 |

**修订 A（主色渐变下调一档）**：

```css
/* v1.0 */ --ac-grad: linear-gradient(135deg,#6366f1,#8b5cf6);   /* 白字 4.2~4.5:1 */
/* v1.1 */ --ac-grad: linear-gradient(135deg,#4f46e5,#7c3aed);   /* 白字 5.7~6.3:1 ✅ */
--ac-glow: rgba(79,70,229,.35);
```

**修订 B（新增文字用主色）**：深底上的强调文字/链接不用 600 级（太暗），单独定义：

```css
--ac-text: #818cf8;   /* on bg-1 ≈ 6.2:1 ✅，用于链接、激活标签、时间码高亮 */
```

> 注：`01-visual-proposal.html` 保留 v1.0 色板作为历史迭代稿，**不回同步**；当前有效色板以本文档与 `03-page-previews.html` 为准。

### 2.2 表面分层使用规则

| 层 | 令牌 | 用途 | 禁止 |
|----|------|------|------|
| bg-0 | `#070A12` | 页面底、demo 画布、播放器黑场 | 放可交互卡片 |
| bg-1 | `#0D1322` | 侧栏、面板容器、玻璃底色 | 直接放正文长段（与 bg-0 差太小） |
| bg-2 | `#151D31` | 海报卡底、输入框、用户芯片 | 用作 hover 态（要用 bg-3） |
| bg-3 | `#1E2942` | hover、按压、菜单项高亮 | 大面积静态使用 |

规则：**相邻两层必须跳一档**（卡片 bg-2 放在页面 bg-0 上，输入框 bg-2 放在面板 bg-1 上），避免 v1.0 诊断里"糊成一片"的问题复发。

### 2.3 间距系统（4px 基数）

```
4 / 8 / 12 / 16 / 20 / 24 / 32 / 48 / 64
```

| 场景 | 值 |
|------|----|
| 卡片内边距 | 12–16 |
| 网格 gap | 16（移动端 10） |
| 区块间距（section 间） | 32 |
| 页面左右边距 | 32（≥1024）/ 24（768–1023）/ 16（<768） |
| 工具栏高度 | 56（桌面）/ 48（移动） |

### 2.4 海拔与阴影（4 级）

| 级 | 阴影 | 使用 |
|----|------|------|
| e0 | 无 | 静态卡片（默认态） |
| e1 | `0 10px 34px rgba(0,0,0,.45)` | 卡片 hover、面板 |
| e2 | `0 18px 50px rgba(0,0,0,.6)` + 主色描边 45% | 悬浮卡片、下拉菜单 |
| e3 | `0 24px 70px rgba(0,0,0,.7)` | Modal、Toast |

**玻璃层规范**（只用于浮层，见 D4）：`backdrop-filter: blur(16px)` + `rgba(13,19,34,.72)` + 内描边 `rgba(255,255,255,.1)`。

### 2.5 Z-index 统一层级表

现状代码 z-index 散落硬编码（web.html L59 `z-[1000]`、L109 `z-[700]`、L118 `z-[750]`、L336 `z-[900]`、L348 `z-[110]`、L47 `z-50`、L25 `z-100`）。收敛为变量：

```css
--z-content: 0;      /* 页面内容 */
--z-sticky: 50;      /* 粘性工具栏、侧栏 */
--z-subtitle: 100;   /* 播放器字幕层 */
--z-player-chrome: 150;  /* 播放器顶栏/控制条 */
--z-menu: 200;       /* 下拉、轨道菜单 */
--z-toast: 400;      /* Toast */
--z-modal: 500;      /* 确认框 */
--z-player-page: 900;    /* 播放器整页 */
--z-login: 1000;     /* 登录页 */
```

### 2.6 动效时长与缓动

| 档 | 时长 | 场景 |
|----|------|------|
| micro | 120ms | hover、按压、图标切换 |
| base | 220ms | 卡片、面板、遮罩 |
| slow | 320ms | 页面切换、浮层出入 |
| enter | 550ms | 列表 stagger 入场（每项延迟 60ms，**最多 8 项后归零**——长列表不能让尾部等 2 秒） |

- 缓动统一 `cubic-bezier(.22,.61,.36,1)`（ease-out 系）；退场类动画用 ease-in 加速。
- 全部位移动画只用 `transform/opacity`（合成层，不触发 layout）。
- 降级：`@media (prefers-reduced-motion: reduce)` 下关闭位移与 stagger，保留透明度过渡。

## 3. 组件状态机

v1.0 只画了默认态。细化补齐交互态与数据缺失分支。

### 3.1 海报卡 `.np-card`

| 状态 | 表现 |
|------|------|
| 默认 | scrim 半显（opacity .92、下移 14px），无播放钮 |
| hover | 上浮 6px、播放钮浮现、scrim 全显、描边 `--ac` 45%、阴影 e2 |
| `:focus-visible` | 同 hover + `outline: 2px solid var(--ac-text); outline-offset: 2px` |
| 按下 | `scale(.98)`（120ms） |
| 拖动滚动中 | 禁用 hover 位移（`pointer-events` 保留，仅去掉 transform，防误触） |

数据缺失分支：

- 无评分 → 隐藏 `★`；无年份 → 只留标题；两者皆无 → scrim 只显标题。
- 无海报图（`ImageTags` 空）→ 渐变兜底 + 居中首字大字（48px，t2 色）。
- 进度条仅在 `0 < PlaybackPositionTicks < 95%` 显示（看完的不再显示）。
- 标题超 2 行截断 + 原生 `title` 属性兜底。

### 3.2 按钮体系（四类 × 三尺寸）

| 类 | 用途 | 默认 | hover | disabled |
|----|------|------|-------|----------|
| `.btn-p` | 主操作（播放/登录） | 渐变 + 光晕 | 上浮 2px + 亮度 1.08 | 40% 透明 + 去阴影 |
| `.btn-g` | 次操作（详情/收藏） | bg-2 + 描边 | 描边主色 + bg-3 | 同上 |
| `.btn-t` | 文字按钮（"重试/展开"） | `--ac-text` | 下划线 | t3 |
| `.ibtn` | 图标按钮 | 透明 | bg-3 圆角块 | 40% 透明 |

- 尺寸：sm 32px / md 38px / lg 46px（主播放钮）；移动端命中区域 ≥ 44px（视觉 38px + 透明 padding 补足）。
- loading 态：图标位置换 16px spinner，**按钮宽度锁定不变**（防抖动）。
- 收藏态：heart 图标填充 + `--danger` 色，切换时 120ms scale 弹跳一次。

### 3.3 玻璃胶囊 `.gpill`（字幕/音轨/版本）

- 点击弹出**向上**菜单（播放器在底部），菜单项 = 轨道列表，当前项左侧 check 图标 + t1，其余 t2。
- 菜单最大高度 60vh 内滚动；`Esc` / 点击外部关闭；打开时胶囊描边主色。
- 轨道名超长（`DisplayTitle` 很长是常态）单行截断 + title。
- 空轨道（无字幕）→ 胶囊整体隐藏，不显示空菜单。

### 3.4 骨架屏 `.skel`

- 形状与最终内容 **1:1**（海报 2:3 + 两行文本），布局零位移。
- 数据到达后 150ms 交叉淡入（骨架 opacity→0 与内容 opacity→1 并行）。
- 超时 8s → 骨架替换为"加载较慢 + 重试按钮"。

## 4. 页面级细化

### 4.1 详情页（v1.0 的缺口，本次补课）

信息架构自上而下：

```
┌ 英雄区 52vh ────────────────────────────┐
│ backdrop 图 + 双向遮罩(底部96% / 左侧60%) │
│  ① 玻璃徽章行 (4K·DV·Atmos·R级)          │
│  ② 剧集导航链接 (S1·E03 · 上一集/下一集)  │
│  ③ 标题 32px + 原名(如有, t2 14px)        │
│  ④ meta 行: 年份·类型·时长·★评分·分级     │
│  ⑤ 简介 line-clamp-3 + [展开/收起]        │
│  ⑥ 操作行: [▶ 播放(副文本:从42:00继续)]   │
│            [♡ 收藏] [⋯ 更多]              │
└──────────────────────────────────────────┘
⑦ 版本区: 卡片式单选(横条: 名称+规格chips+码率)
⑧ 季分段控件(sticky) + 剧集列表(行式卡片)
⑨ 音频/字幕轨道: 双列(md+)/单列(移动)
```

关键决策：

- **版本选择从 `<select>`（web.html L250）升级为卡片式单选**：每个版本一条横卡（名称 · 容器 · 规格 chips · 码率），选中项主色描边。多版本是本产品核心卖点（多服务器聚合），select 藏住了信息。小屏（<640）回退 select 省纵向空间。
- **季切换用分段控件**替代现状"每季一个大标题 + 一大段列表"（L257-277）：`第 1 季 | 第 2 季 | …` 横向分段，sticky 在工具栏下，切季只换列表不换页。
- **剧集行**：`[16:9 缩略图 132px] [E03·标题·时长·进度条] [hover:圆形播放钮]`；已看集整行 `opacity:.55` + 缩略图右上角 ✓ 角标。
- 播放按钮副文本：`UserData.PlaybackPositionTicks > 0` 时显示"从 42:00 继续"，点击带 `startSeconds`（数据链路已支持）。

### 4.2 媒体库页

- 顶部**粘性工具栏**：滚动 8px 后收窄成胶囊（高度 56→44，背景转玻璃），含流派筛选、排序、视图切换（网格/列表）。
- **无限滚动**替代"加载更多"按钮（L204-206）：`IntersectionObserver` 哨兵元素距底 600px 触发；保留按钮做兜底（IO 不可用/失败时显示）。
- 空状态：插画 + "该筛选下暂无内容" + [清除筛选]。

### 4.3 搜索页

- 输入防抖已有（400ms）；补**最近搜索**（localStorage，最多 8 条，聚焦且输入为空时显示，可单条删除）。
- 结果分组：电影 / 剧集 两节，各带小节标题与计数。
- 无结果空状态：`未找到 "xxx"` + [清除] + 建议词（取最近搜索第一条）。

### 4.4 登录页

- 错误提示从顶部红条（L66）改为**输入框下方行内错误**（`--danger` 12.5px）+ 输入框描边红 + 220ms 水平抖动一次。
- 密码框补"显示密码"眼睛图标（`ibtn` 内嵌右侧）。
- 品牌区背景可选增强：模糊海报轮播（P3，默认纯渐变即可）。

## 5. 播放器交互细化

### 5.1 控制条自动隐藏

```
状态: visible ──(playing && 无操作 3s)──> hidden
      hidden  ──(mousemove / touch / 暂停 / 悬停控制条)──> visible
hidden 表现: opacity 0 + pointer-events none + cursor: none
```

- 拖动进度、悬停控制条期间强制 visible；暂停时常显。
- 移动端：单击画面切换 visible/hidden（桌面单击=播放/暂停切换，见 D7）。

### 5.2 进度条

- hover：高度 4→6px、thumb 缩放浮现、**时间气泡跟随鼠标 x**（v1.0 是固定位置，需修正）。
- 拖动中：气泡常显、进度条保持 6px、松手后 220ms 回落。
- 缓冲条 `.buf`：native 模式读 `video.buffered` 末段；libmedia 模式读缓存区间，取不到就隐藏（不显示假数据）。
- 缩略图预览（P3）：依赖上游 sprite/tile 接口，先留接口位。

### 5.3 键盘快捷键（全局，播放页内）

| 键 | 行为 |
|----|------|
| `Space` / `K` | 播放/暂停 |
| `←` / `→` | ∓10s（按住连续） |
| `J` / `L` | ∓10s（YouTube 习惯兼容） |
| `↑` / `↓` | 音量 ±5% |
| `M` | 静音 |
| `F` | 全屏 |
| `C` | 字幕开/关（回到上次轨道） |
| `Esc` | 退出全屏 → 退出播放器 |

- 快捷键触发时对应按钮闪一次 hover 态（视觉反馈因果，P4）。
- 输入框聚焦时快捷键失效（`e.target` 判断）。

### 5.4 其他

- 暂停时画面中央淡入大播放钮（96px，半透玻璃），播放时淡出。
- 双击画面 = 全屏切换（桌面）；单击 = 播放/暂停。
- 音量图标三态：>50% 大喇叭 / 1-50% 小喇叭 / 0 静音斜杠；点击图标 = 静音切换。
- 顶栏（关闭+标题）与控制条同步隐藏逻辑。

## 6. 反馈系统：Toast / 空状态 / 加载

### 6.1 Toast（替代 alert）

现状 `app.js` 多处 `alert()`（播放错误、音轨切换失败、L608-611 等）——模态打断 + 丑。替换为：

- 位置：右下（≥768）/ 顶部居中（<768）；`--z-toast`。
- 类型：info（t2 描边）/ success（`--atmos` 左条）/ error（`--danger` 左条）。
- 自动消失 2.5s（error 4s），hover 暂停计时；最多同屏 3 条，超出挤掉最旧。
- 结构：`[类型色条 3px] [图标] [文案] [关闭×]`，玻璃底。

### 6.2 空状态规范

每页一个：简单 SVG 场景插画（120px，t3 线稿风）+ 主文案（t1）+ 副文案（t2）+ 行动按钮（`btn-t`）。

| 页 | 主文案 | 行动 |
|----|--------|------|
| 继续观看 | 还没有观看记录 | 去首页逛逛 → |
| 收藏 | 还没有收藏 | 打开影片点 ♥ 收藏 |
| 库筛选 | 该筛选下暂无内容 | 清除筛选 |
| 搜索 | 未找到 "xxx" | 清除搜索词 |

### 6.3 加载层级

路由切换 → 旧内容 120ms 淡出（防白闪）→ 骨架屏 → 数据交叉淡入。播放器内保留 spinner 遮罩（wasm 加载有真实进度文案，L343-346 已有）。

## 7. 移动端策略
> **v1.2 决议（D13）**：本节整体延后——播放器桌面形态未定型，移动端待其稳定后单独出 375px 视觉稿评审。以下规范保留作未来参考。

### 7.1 底部标签栏（替代汉堡菜单）

现状汉堡菜单（L109-129）是桌面思路的移植；媒体类 App 拇指操作应以底部标签栏为主导航：

```
[ 首页 ] [ 继续观看 ] [ 收藏 ] [ 搜索 ]
   56px 高 + safe-area-inset-bottom，玻璃底
```

- 激活项：图标 + 文字 t1 + 顶部 3px 渐变条；未激活 t3。
- 播放页、登录页隐藏标签栏。
- 保留顶栏放标题/返回（详情页、库页）。
- **待实测**（见开放问题 Q3）：4 项刚好，未来加项需重议。

## 8. 无障碍与性能底线

**无障碍（验收项）**

- 对比度：t1/t2 全场景 AA；t3 仅装饰（见 2.1 实测）。

**性能**

- `backdrop-filter` 只用于浮层（控制条、菜单、Toast、标签栏），列表卡片一律不用（低端安卓开销，见 D4）。

- 滚动条全局美化：`scrollbar-width: thin; scrollbar-color: var(--bg-3) transparent`。

| # | 决策 | 理由 |

## 13. v1.2 修订（评审结论）

> 与维护者评审后的落地结论：首页信息架构、数据源成本核实、导航收敛、移动端排期。对应预览更新见 `03-page-previews.html`。

### 13.1 首页行序调整（D10）

```
Hero → 继续观看 → 媒体库 → 最新
```

续看是意图最高的内容（用户上次中断处），应占据 Hero 之下第一屏；媒体库是低频导航入口，下移一位。

### 13.2 媒体库卡不显示计数（D11）

- 现状 `loadHome()` 只调 `Views` + 每库一次 `Latest`，无任何计数请求；首页卡片显示计数必须新增上游调用
- 上游 `/Items/Counts` 后端未实现；多服务器聚合下首页一次加载将多出 N(库)×M(服务器) 个上游请求
- 本项目核心卖点是"行为像真实客户端"，首页突发并发有触发上游异常检测的风险
- **由此确立原则：首页零新增上游调用**——首页所有信息必须复用现有 Views/Latest 响应
- 区分：**媒体库页**标题旁的计数保留——它来自现有 Items 查询自带的 `TotalRecordCount`（app.js L269 已在用），零额外成本
- 若未来确需首页计数：SQLite 本地缓存 + 6-24h TTL 后台静默刷新（上游每天每库约 1 次）。首期否决
- **v1.3 豁免**：「接下来观看」行的 NextUp 调用（D17）为单次轻量请求，不属 N×M 扩散，豁免本原则；详见 §15.2

### 13.3 数据源核实结论

| 数据 | 来源 | 额外成本 | 结论 |
|------|------|----------|------|
| 评分 `CommunityRating` | Items 响应标准字段 | 0（加入 Fields） | 可靠；缺失时隐藏星标 |
| 年份 `ProductionYear` | Fields 已显式请求（app.js L263） | 0 | 现有 UI 已在显示 |
| 流派标签 | `/Genres?ParentId=` | 0 | 后端已实现聚合去重（library_image.go），app.js L242 已在调用；失败不阻塞列表（空数组兜底）。胶囊化纯 UI 改动；流派多时需横向滚动或折叠 |
| 分级 `OfficialRating` | 上游刮削器（TMDB/OMDb）填充 | 0 | 详情 Fields 已显式请求（L297），现有 UI 已渲染；缺失时隐藏。不同库刮削体系可能不同（R/PG-13 美标等），仅展示不做事 |

### 13.4 侧栏导航收敛（D12）

```
首页 / 收藏 / 搜索        （原：首页 / 继续观看 / 收藏 / 搜索）
```

- 继续观看是**被动状态**（看一半自然产生），首页一屏 + 行头"全部 ›"足够
- 收藏是**主动行为**，需要稳定导航入口
- `#/resume` 路由**保留**：首页"继续观看 · 全部 ›"链入，深链与完整列表能力不丢
- 移动端底部标签栏同步 4→3 项（随 §7 延后）

### 13.5 移动端适配延后（D13）

播放器桌面形态尚未定型（解码路径、轨道切换交互仍在演进），移动端适配（底部抽屉、三件套控制条、底部标签栏）**整体延后**，待播放器设计稳定后单独出 375px 视觉稿评审。§7 全节标记为暂缓参考。

## 14. 防御性状态与异常路径设计

> v1.3 新增。多服务器聚合产品中**部分失败是常态而非异常**（README L76：某台上游离线时自动回退其他实例）。此前设计只覆盖正常路径，本节补齐失败路径。每项标注**代码接口锚点**（现有文件/行号/字段），供执行模型直接对接，不涉及实现代码。

### 14.0 总原则（D14）

每个数据依赖区块必须具备三态：**降级**（数据缺失时隐藏或占位，不报错）、**重试**（失败时行动按钮）、**部分失败**（聚合部分成功时提示不完整）。禁止把局部失败渲染成整页错误。

### 14.1 异常状态规范表

| # | 状态 | 代码接口锚点 | 触发条件 | UI 表现 | 恢复动作 |
|---|------|--------------|----------|---------|----------|
| E1 | **429 并发拒播** | 后端 `maxConcurrent` 超限返回 429（README L74）；前端 `api()` 抛错（app.js L26-32），PlaybackInfo 调用点 L561 | 点击播放/切版本时 | 播放器内**专用错误卡**（非普通播放失败）：图标 + 标题"服务器并发已满" + 副文案"当前服务器播放数已达上限，稍后自动释放" + [稍后重试] + [切换其他版本]（若多版本） | 手动重试；倒计时自动重试（可选） |

### 14.2 播放器状态机补全

此前 §5 只定义了控制条 visible/hidden。补全播放引擎状态（数据源：`instance.onState` 回调，app.js L590-599 已上报 mode/playing/time/duration/loading/message）：

- `idle`：未加载。进入条件：播放器销毁。

**安全设计（api_key 直链提示，本功能的核心约束）**：

事实基础（均已代码核实）：

- 直链携带的 `api_key` = 当前用户完整会话令牌（`eio_token`，localStorage）；**运行期间永不过期**（auth_manager.go L242-261 `ValidateToken` 无过期分支；coverage_gaps_test.go L218 `TestTokenNeverExpires` 固化该行为），仅服务重启（令牌为内存态）或 `RevokeToken`（L263）可使其失效
- Web 客户端令牌被刻意限制为非管理员（handlers_user.go L41-53 拒绝管理员经 Web 登录），泄露面 = 该用户的媒体库读 + 播放 + 观看状态写
- redirect（直连）模式下 302 目标含上游凭据——管理端已有先例警告（admin_validation.go L181 `redirectCredentialWarning`：「直连播放模式会把上游账号凭据写入跳转链接……相当于上游管理员权限」）；用户端提示对齐同一口径，但前端无法感知该上游的模式，故按最保守口径统一提示

弹窗警示文案（固定展示，不折叠）：

> 链接包含你的访问令牌（api_key），等同于登录凭证且不会过期。请勿分享给他人或粘贴到公开场合；剪贴板历史（如 Win+V）与外部播放器的播放记录都可能留存它。服务重启后链接自动失效。

**上游视角矩阵（两种模式下上游看到的身份，均已代码核实）**：

| 模式 | 上游看到的 UA | 上游看到的 IP | 设备记录影响 |
|------|--------------|--------------|--------------|
| 代理 + passthrough（部署中有真实客户端连过 EIO） | 该真实客户端的身份（解析链 identity.go L144-162：live-request → captured-token → last-success → captured-latest） | EIO 服务器 IP | 无新增，完全隐形 |
| 代理 + custom / 未配置 | 管理员配置 UA（upstream.go L998-1012）/ Go 默认 UA | EIO 服务器 IP | 视配置 |
| 直连 redirect | **VLC/Infuse 本尊 UA** | **用户设备真实 IP** | **上游新增一条外部播放器设备记录** |

三个关键事实：

1. **直连模式下 EIO 身份体系完全旁路**：EIO 只发一次 302（media_stream.go L86-98）即退出数据路径，播放器直连上游——上游看到的是播放器本尊（UA + 用户 IP + URL 内上游凭据）。在意上游设备记录/检测的用户，**代理模式 + passthrough 是唯一完全隐形的路径**
2. **passthrough 的捕获来源是真实 Emby 客户端，不是网页浏览器**：Web 客户端刻意不发 X-Emby-* 头（app.js L19-21），浏览器 UA 也不含 emby/infuse/jellyfin 关键字（identity.go L463-469 `hasPassthroughIdentity` 判定），网页登录不产生捕获；若部署中从未有真实客户端（Infuse 等）连过 EIO，代理模式解析到 no-identity（upstream.go L1014-1017，宁可不伪装也不伪造）
3. **代理模式下 VLC 自己的 UA 也不会被转发**：`streamRequestHeaders` 白名单仅 Range/Accept/Accept-Encoding/Accept-Language（media_stream.go L275-283），VLC 的头不满足 passthrough 判定（无 X-Emby-*、UA 无关键字），上游看到的 UA 始终来自身份解析链

设计含义：弹窗警示文案不区分模式（前端无法感知该上游配置），但**文档与 README 需向管理员说明**——若部署目标是"上游零新增设备记录"，外部播放器功能应配合代理模式使用；直连模式下每次外部播放都会在上游留下播放器设备痕迹。

**边界**：

- **剪贴板双路径（自托管主场景）**：`navigator.clipboard` 仅在 secure context（HTTPS / localhost）可用；`http://192.168.x.x` 局域网部署必须回退 `document.execCommand('copy')` + 临时 textarea。两路径都失败 → 输入框全选 + 提示「请手动 Ctrl+C」
- **deep link 不做安装检测**：自定义协议无法可靠探测是否注册；未安装时点击无反应，弹窗文案注明「未安装请复制直链手动添加」
- **进度不同步**：外部播放不上报观看进度（无 PlaySession 上报），Toast 提示 + F3 手动已看标记兜底
- **字幕限制**：外挂字幕轨不会自动加载（URL scheme 不支持字幕参数）；内嵌字幕轨（含 PGS/ASS）由播放器原生解码——恰是外部播放器的优势所在
- **可达性**：直链可达范围 = 当前访问 origin 的可达范围（LAN IP 出局域网即失效；公网域名则随处可用）
- **不提供转码直链**：外部播放器的价值就是原生直解原文件；带宽受限场景网页播放器的 HLS 转码已是正解。单一 URL = 单一事实源

**可选增强（tier-2，非本版）**：短期直链令牌——新增签发端点（如 `POST /web/links`）产出 30 分钟单用途 token，从根上收窄"永不过期"泄露面；因需新增后端端点、违背 §16 零后端改动基调，列为后续独立决策（D23 候选）。
