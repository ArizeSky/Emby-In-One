DESIGN PROPOSAL · V1

/web UI 优化方案

针对 public/web/web.html（390 行单文件 Vue 3 + Tailwind 客户端）的纯视觉层改造：不动数据流、不动 app.js 业务逻辑（Hero 轮播除外），通过设计令牌、组件重绘与动效体系，把"后台管理面板感"升级为"流媒体产品感"。

目标文件 public/web/web.html 改动范围 仅 <style> 块 + 模板类名 + 少量结构 新增依赖 无 预计工作量 1 人日

01

现状诊断

当前 UI 的问题不在功能，而在"视觉语言"：所有界面共用同一种扁平灰蓝面板、默认蓝按钮，没有任何媒体产品应有的层次、焦点与氛围。六个核心问题：

① 表面扁平，无层级
侧栏、卡片、输入框全部是同一档 slate-800 灰，前后景没有深浅差，界面"糊"成一片。
② 无品牌记忆点
默认 Tailwind blue-600 按钮 + 无渐变、无光效、无图形语言，任何后台模板都长这样。
← 与千篇一律的后台无异
③ 海报卡信息密度低
hover 只有 scale(1.03)，无播放入口、无评分、无年份、无观看进度，用户必须点进详情才能决策。

④ 首页没有焦点区
媒体库是图标方块、内容直接铺海报网格，页面没有视觉锚点，像列表页而不是"首页"。
▣ 电影

⑤ 播放器控件"文字化"
"暂停/上一集/下一集"是文字按钮，版本/音轨/字幕挤成一排 select，工具栏像表单不像播放器。
⑥ 加载/空状态粗糙
全页共用一个 40px spinner，空状态是一行灰字，等待期间界面"塌陷"。

06

落地清单

按依赖顺序实施；除 Hero 轮播外全部是 CSS / 模板层改动，不触碰 app.js 数据流与 player-libmedia.js 播放内核。

改动点位置（web.html）做法工作量
① 设计令牌<style> 顶部新增 :root{--bg-0…} 变量集；把模板里的 bg-slate-900/800/700 批量替换为 var(--bg-0/1/2) 对应类小
② 海报卡片.poster-card + HOME/LIBRARY 模板重写为 .np-card：遮罩、播放钮、评分/年份、进度条结构（数据字段 CommunityRating/ProductionYear/UserData 均已存在）中
③ Hero 焦点区HOME 模板顶部 + app.js新增 section；app.js 取 latestSections 第一区前 5 项做 8s 轮播（约 30 行，唯一 JS 改动）中
④ 媒体库卡HOME「媒体库」区块图标方块改为封面背景卡（背景可直接用 imageUrl(lib 首项) 或纯渐变兜底）小
⑤ 播放器工具栏.play-toolbar + PLAYER 模板文字按钮换 lucide 图标（skip-back/play/skip-forward/volume-2/maximize），select 换玻璃胶囊；进度条加 .buf 缓冲层与悬停时间气泡中
⑥ 登录分栏LOGIN 区块改为品牌/表单两栏 grid，窄屏单栏；按钮套用 .btn-p小
⑦ 规格徽章.chip*实心色块 → 玻璃胶囊 + 指示点（保留 4K/DV/Atmos 色语义）小
⑧ 骨架屏各 loading 区块spinner 替换为 .skel 骨架（海报形状 + 文本行），布局不塌陷小
⑨ 动效体系<style>统一 --ease/--dur；卡片 hover 由 scale 改 translateY(-6px)；列表入场 stagger（纯 CSS animation-delay）小
⑩ 侧栏激活态aside nav实心蓝块 → 渐变胶囊 + 左侧光条；底部加用户芯片（数据已有 currentUser）小
两个注意点： ① 现有 v-cloak 与 lucide refreshIcons() 机制不受影响——新组件仍用 data-lucide 图标即可； ② 播放器控制条改图标后，移动端 @media(max-width:640px) 需同步收窄间距（图标化后反而比文字按钮更省横向空间）。
